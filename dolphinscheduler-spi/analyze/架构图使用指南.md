## 📖 三个简化版架构图详解

### 1. spi-core-flow.puml - 核心流程图（极简）

```
业务代码
    ↓
Provider (门面)
    ↓
PluginManager (管理器)
    ↓
Channel (通道)
    ↓
    ├─→ AdHoc Client ─→ Processor ─→ Connection
    └─→ Pooled Client ─→ HikariCP ─→ Connection
```

**优势**：
- 🎯 最简洁，一眼看懂
- 🎯 使用活动图（activity diagram）
- 🎯 展示两种路径的分支
- 🎯 适合快速理解

---

### 2. spi-architecture-flow.puml - 流程架构图（简洁）

```
┌──────────────────┐
│    业务代码       │
└────────┬─────────┘
         ↓
┌────────┴─────────┐
│   门面层          │
│   Provider       │
└────────┬─────────┘
         ↓
┌────────┴─────────┐
│   管理层          │
│   PluginMgr      │
└────────┬─────────┘
         ↓
... (依次向下)
```

**优势**：
- 🎯 纵向流程，清晰直观
- 🎯 分层展示，职责明确
- 🎯 减少交叉连线
- 🎯 适合理解层次结构

---

### 3. spi-architecture-layered.puml - 分层架构图（中等）

```
第1层: 业务层
第2层: 门面层
第3层: 管理层
第4层: SPI 契约层
第5层: 实现层
第6层: 插件层
```

**优势**：
- 🎯 横向分层，一目了然
- 🎯 每层职责清晰
- 🎯 自上而下的依赖关系
- 🎯 适合理解系统分层

---

### 4. spi-architecture-simple.puml - 简化组件图（中等）

包含核心组件：
- ✅ SPI 机制（PrioritySPI, SPIFactory）
- ✅ 数据源抽象（Channel, ChannelFactory, ConnectionParam）
- ✅ 客户端抽象（Client, AdHoc, Pooled）
- ✅ 管理层（PluginManager, ProcessorProvider）
- ✅ 实现层（BaseAdHoc, BasePooled, Processor）

**优势**：
- 🎯 比完整版简洁
- 🎯 保留核心组件
- 🎯 简化关系线
- 🎯 适合学习组件关系
