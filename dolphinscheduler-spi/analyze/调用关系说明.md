# DataSourceClientProvider 实际调用关系说明

## 🔍 关键澄清

### ❌ 错误理解
```
DataSourceClientProvider → DataSourceProcessorProvider
```

### ✅ 正确关系
```
DataSourceClientProvider → DataSourcePluginManager → DataSourceChannel
    ↓
DataSourceClient (AdHoc/Pooled)
    ↓ (仅 AdHoc 路径)
DataSourceProcessorProvider → DataSourceProcessor
```

---

## 🎯 实际调用链路

### 链路 1: Pooled 池化连接（不使用 Processor）

```java
// 1. 业务代码调用
Connection conn = DataSourceClientProvider
    .getPooledConnection(DbType.MYSQL, params);

// 2. Provider 内部实现
public static Connection getPooledConnection(DbType dbType, ConnectionParam params) {
    // 2.1 获取 Channel
    DataSourceChannel channel = dataSourcePluginManager
        .getDataSourceChannelMap()
        .get(dbType.getName());  // "mysql"
    
    // 2.2 创建 Client
    PooledDataSourceClient client = channel
        .createPooledDataSourceClient(
            (BaseConnectionParam) params, 
            dbType
        );
    
    // 2.3 获取连接
    return client.getConnection();
}

// 3. Client 实现
public class MySQLPooledDataSourceClient extends BasePooledDataSourceClient {
    
    public MySQLPooledDataSourceClient(BaseConnectionParam params, DbType dbType) {
        super(params, dbType);
        // 构造时创建连接池
        this.dataSource = createDataSourcePool(params, dbType);
    }
    
    @Override
    public HikariDataSource createDataSourcePool(
            BaseConnectionParam params, DbType dbType) {
        HikariDataSource ds = new HikariDataSource();
        ds.setDriverClassName(params.getDriverClassName());
        ds.setJdbcUrl(params.getJdbcUrl());
        ds.setUsername(params.getUser());
        ds.setPassword(params.getPassword());
        // ... 配置连接池参数
        return ds;
    }
    
    @Override
    public Connection getConnection() throws SQLException {
        // 从连接池获取（不调用 Processor）
        return dataSource.getConnection();
    }
}
```

**关键点**：
- ✅ Provider **只依赖** PluginManager
- ✅ 创建连接池时使用 **BaseConnectionParam** 中的参数
- ✅ `getConnection()` 直接从池中获取，**不需要 Processor**

---

### 链路 2: AdHoc 临时连接（使用 Processor）

```java
// 1. 业务代码调用
Connection conn = DataSourceClientProvider
    .getAdHocConnection(DbType.MYSQL, params);

// 2. Provider 内部实现
public static Connection getAdHocConnection(DbType dbType, ConnectionParam params) {
    // 2.1 获取 Channel
    DataSourceChannel channel = dataSourcePluginManager
        .getDataSourceChannelMap()
        .get(dbType.getName());
    
    // 2.2 创建 Client
    AdHocDataSourceClient client = channel
        .createAdHocDataSourceClient(
            (BaseConnectionParam) params, 
            dbType
        );
    
    // 2.3 获取连接
    return client.getConnection();
}

// 3. Client 实现
public class MySQLAdHocDataSourceClient extends BaseAdHocDataSourceClient {
    
    public MySQLAdHocDataSourceClient(BaseConnectionParam params, DbType dbType) {
        super(params, dbType);
        // 只保存参数，不创建连接
    }
    
    @Override
    public Connection getConnection() throws SQLException {
        // 关键：这里调用 DataSourceProcessorProvider
        return DataSourceProcessorProvider
            .getDataSourceProcessor(dbType)  // 获取 Processor
            .getConnection(baseConnectionParam);  // 创建新连接
    }
}

// 4. Processor 实现
public class MySQLDataSourceProcessor implements DataSourceProcessor {
    
    @Override
    public Connection getConnection(ConnectionParam params) throws Exception {
        Class.forName(getDatasourceDriver());
        String jdbcUrl = getJdbcUrl(params);
        
        // 每次都创建新连接
        return DriverManager.getConnection(
            jdbcUrl,
            params.getUser(),
            params.getPassword()
        );
    }
}
```

**关键点**：
- ✅ Provider **只依赖** PluginManager
- ✅ **BaseAdHocDataSourceClient** 内部调用 ProcessorProvider
- ✅ 每次调用 `getConnection()` 都通过 Processor 创建新连接

## 📊 依赖关系对比

### DataSourceClientProvider 的依赖

```
DataSourceClientProvider
    │
    └─→ 直接依赖: DataSourcePluginManager
            └─→ 提供: Map<String, DataSourceChannel>

不直接依赖: DataSourceProcessorProvider
            (由 BaseAdHocDataSourceClient 内部调用)
```

### 完整依赖链

```
业务代码
    ↓ 调用
DataSourceClientProvider (门面)
    ↓ 依赖
DataSourcePluginManager (管理器1)
    ↓ 返回
DataSourceChannel (通道)
    ↓ 创建
DataSourceClient (客户端)
    ├─ PooledDataSourceClient
    │   └─ getConnection() → pool.getConnection()
    │      (不需要 Processor)
    │
    └─ AdHocDataSourceClient
        └─ getConnection()
            ↓ 内部调用
        DataSourceProcessorProvider (提供者)
            ↓ 依赖
        DataSourceProcessorManager (管理器2)
            ↓ 返回
        DataSourceProcessor (处理器)
            ↓ 调用
        DriverManager.getConnection()
            ↓
        Connection
```

## 🔄 两种路径的对比

### Pooled 路径（不经过 Processor）

```
Provider
  ↓
PluginManager
  ↓
Channel
  ↓
PooledClient
  ↓ (构造时配置连接池)
HikariDataSource
  ↓ (运行时从池获取)
Connection
```

**不需要 DataSourceProcessor**，因为：
- 连接池参数从 `BaseConnectionParam` 直接获取
- 初始化时 HikariCP 内部自己创建连接
- 运行时从池中获取，不需要再创建

---

### AdHoc 路径（经过 Processor）

```
Provider
  ↓
PluginManager
  ↓
Channel
  ↓
AdHocClient
  ↓ (getConnection 时)
ProcessorProvider
  ↓
ProcessorManager
  ↓
Processor
  ↓
DriverManager
  ↓
Connection
```

**需要 DataSourceProcessor**，因为：
- 每次都要创建新连接
- 需要 Processor 提供 JDBC URL、驱动类名等
- 需要 Processor 处理数据库特定逻辑

---

## 💡 为什么这样设计？

### 1. 职责分离

```
DataSourceClientProvider (门面)
    职责: 提供简单的 API
    不关心: 连接如何创建

DataSourcePluginManager (管理器)
    职责: 管理 Channel
    不关心: Processor

BaseAdHocDataSourceClient (客户端)
    职责: 创建连接
    需要: Processor 帮助
    自己调用: ProcessorProvider
```

### 2. 最小依赖

```
Provider 只依赖 PluginManager
    ↓ 好处
• Provider 不需要知道 Processor
• 降低耦合
• 职责更单一
```

### 3. 策略灵活

```
Pooled 客户端: 不需要 Processor
    ↓ 原因
• HikariCP 自己管理连接
• 参数已经在 BaseConnectionParam 中
• 减少依赖

AdHoc 客户端: 需要 Processor
    ↓ 原因
• 每次创建新连接
• 需要数据库特定逻辑
• 适配不同数据库差异
```

## 📝 总结

### 正确的理解

1. **DataSourceClientProvider**
   - 只依赖 `DataSourcePluginManager`
   - 通过 PluginManager 获取 `DataSourceChannel`
   - 不直接依赖 `DataSourceProcessorProvider`

2. **DataSourceProcessorProvider**
   - 被 `BaseAdHocDataSourceClient` 调用
   - 提供 `DataSourceProcessor`
   - 只在 AdHoc 路径中使用

3. **调用层次**
   ```
   Provider (门面层)
       ↓
   PluginManager (管理层)
       ↓
   Channel (工厂层)
       ↓
   Client (客户端层)
       ↓ (AdHoc 才需要)
   ProcessorProvider → Processor (处理器层)
   ```

### 架构优势

✅ **解耦**: Provider 不直接依赖 Processor  
✅ **灵活**: 两种路径不同的依赖  
✅ **清晰**: 职责明确，层次分明  

---

这样的设计让架构更加优雅和灵活！🎉
