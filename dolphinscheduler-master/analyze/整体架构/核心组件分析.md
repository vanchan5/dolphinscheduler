# DolphinScheduler Master 核心组件详细分析

## 1. MasterServer 启动流程详解

### 1.1 启动入口

```java
public static void main(String[] args) {
    // 1. 注册未捕获异常监控
    MasterServerMetrics.registerUncachedException(DefaultUncaughtExceptionHandler::getUncaughtExceptionCount);
    
    // 2. 设置默认异常处理器
    Thread.setDefaultUncaughtExceptionHandler(DefaultUncaughtExceptionHandler.getInstance());
    
    // 3. 设置线程名称
    Thread.currentThread().setName(Constants.THREAD_NAME_MASTER_SERVER);
    
    // 4. 启动 Spring Boot 应用
    SpringApplication.run(MasterServer.class);
}
```

### 1.2 初始化流程 (@PostConstruct)

```java
@PostConstruct
public void initialized() {
    // 1. 设置服务器状态为 RUNNING
    ServerLifeCycleManager.toRunning();
    
    // 2. 启动 RPC 服务器
    this.masterRPCServer.start();
    
    // 3. 加载任务插件和数据源处理器
    TaskPluginManager.loadTaskPlugin();
    DataSourceProcessorProvider.initialize();
    
    // 4. 启动注册客户端
    this.masterRegistryClient.start();
    this.masterRegistryClient.setRegistryStoppable(this);
    
    // 5. 启动集群管理器
    this.clusterManager.start();
    this.clusterStateMonitors.start();
    
    // 6. 启动工作流引擎
    this.workflowEngine.start();
    
    // 7. 启动调度器 API
    this.schedulerApi.start();
    
    // 8. 发布全局 Master 故障转移事件
    this.systemEventBus.publish(GlobalMasterFailoverEvent.of(new Date(startupTime)));
    this.systemEventBusFireWorker.start();
    
    // 9. 注册指标监控
    registerMetrics();
    
    // 10. 注册关闭钩子
    Runtime.getRuntime().addShutdownHook(new Thread(() -> {
        if (!ServerLifeCycleManager.isStopped()) {
            close("MasterServer shutdownHook");
        }
    }));
}
```

### 1.3 关闭流程

```java
@PreDestroy
public void shutdown() {
    close("MasterServer shutdown");
}

public void close(String cause) {
    // 1. 设置停止信号
    if (!ServerLifeCycleManager.toStopped()) {
        log.warn("MasterServer is already stopped, current cause: {}", cause);
        return;
    }
    
    // 2. 等待线程安静停止
    ThreadUtils.sleep(Constants.SERVER_CLOSE_WAIT_TIME.toMillis());
    
    // 3. 关闭资源（使用 try-with-resources）
    try (
        SystemEventBusFireWorker systemEventBusFireWorker1 = systemEventBusFireWorker;
        WorkflowEngine workflowEngine1 = workflowEngine;
        SchedulerApi closedSchedulerApi = schedulerApi;
        MasterRpcServer closedRpcServer = masterRPCServer;
        MasterRegistryClient closedMasterRegistryClient = masterRegistryClient;
        SpringApplicationContext closedSpringContext = springApplicationContext
    ) {
        log.info("Master server is stopping, current cause : {}", cause);
    } catch (Exception e) {
        log.error("MasterServer stop failed, current cause: {}", cause, e);
    }
}
```

## 2. CommandEngine 命令处理详解

### 2.1 命令获取策略

**接口**: `ICommandFetcher`

**实现**:
- 从数据库 `t_ds_command` 表获取命令
- 支持按 Slot 分片获取
- 支持批量获取
- 支持命令去重

### 2.2 命令处理流程

```java
@Override
public void run() {
    while (flag) {
        try {
            // 1. 检查服务器负载
            SystemMetrics systemMetrics = metricsProvider.getSystemMetrics();
            if (serverLoadProtection.isOverload(systemMetrics)) {
                log.warn("The current server is overload, cannot consumes commands.");
                Thread.sleep(Constants.SLEEP_TIME_MILLIS);
                continue;
            }
            
            // 2. 获取命令列表
            List<Command> commands = commandFetcher.fetchCommands();
            if (CollectionUtils.isEmpty(commands)) {
                Thread.sleep(Constants.SLEEP_TIME_MILLIS);
                continue;
            }
            
            // 3. 并发处理命令
            List<CompletableFuture<Void>> allCompleteFutures = new ArrayList<>();
            for (Command command : commands) {
                CompletableFuture<Void> completableFuture = bootstrapCommand(command)
                        .thenAccept(this::bootstrapWorkflowExecutionRunnable)
                        .thenAccept((unused) -> bootstrapSuccess(command))
                        .exceptionally(throwable -> bootstrapError(command, throwable));
                allCompleteFutures.add(completableFuture);
            }
            CompletableFuture.allOf(allCompleteFutures.toArray(new CompletableFuture[0])).join();
        } catch (InterruptedException e) {
            break;
        } catch (Exception e) {
            log.error("Master schedule workflow error", e);
            ThreadUtils.sleep(Constants.SLEEP_TIME_MILLIS);
        }
    }
}
```

## 5. 任务分发机制详解

### 5.1 任务分发流程

```
1. WorkflowExecutionGraph 提交任务
   ↓
2. 创建 TaskExecutionRunnable
   ↓
3. 放入 GlobalTaskDispatchWaitingQueue
   ↓
4. GlobalTaskDispatchWaitingQueueLooper 循环处理
   ↓
5. 根据任务类型选择 TaskDispatcher
   ↓
6. TaskDispatcher 选择目标节点
   ↓
7. 通过 RPC 分发任务
   ↓
8. 更新任务状态为 DISPATCH
```

### 5.2 Worker 任务分发

**类**: `WorkerTaskDispatcher`

**流程**:
1. 获取任务的 Worker 组
2. 通过负载均衡器选择 Worker 节点
3. 设置任务执行上下文的主机地址
4. 调用 Worker RPC 接口分发任务

**RPC 接口**: `ITaskInstanceOperator.dispatchTask()`

### 5.3 Master 任务分发

**类**: `MasterTaskDispatcher`

**流程**:
1. 获取 Master 地址
2. 设置任务执行上下文的主机地址
3. 调用 Master RPC 接口分发逻辑任务

**RPC 接口**: `ILogicTaskInstanceOperator.dispatchLogicTask()`

### 5.4 负载均衡策略

**接口**: `IWorkerLoadBalancer`

**实现**:
- `RoundRobinWorkerLoadBalancer`: 轮询
  - 按顺序选择 Worker 节点
  - 简单高效
  
- `RandomWorkerLoadBalancer`: 随机
  - 随机选择 Worker 节点
  - 适合负载均衡
  
- `FixedWeightedRoundRobinWorkerLoadBalancer`: 固定权重轮询
  - 根据固定权重选择 Worker 节点
  - 支持配置权重
  
- `DynamicWeightedRoundRobinWorkerLoadBalancer`: 动态权重轮询
  - 根据 Worker 节点状态动态调整权重
  - 考虑 CPU、内存等指标

## 7. 故障转移机制详解

### 7.1 Master 故障转移

**触发条件**:
- Master 节点从注册中心消失
- Master 心跳超时

**处理流程**:
1. `ClusterStateMonitors` 检测到 Master 节点消失
2. 发布 `MasterFailoverEvent` 事件
3. `FailoverCoordinator.failoverMaster()` 处理故障转移
4. 获取需要故障转移的工作流实例
5. `WorkflowFailover.failoverWorkflow()` 处理每个工作流
6. 更新工作流状态为 `FAILOVER`
7. 创建故障转移命令
8. 插入命令到数据库
9. `CommandEngine` 重新处理命令

### 7.2 Worker 故障转移

**触发条件**:
- Worker 节点从注册中心消失
- Worker 心跳超时

**处理流程**:
1. `ClusterStateMonitors` 检测到 Worker 节点消失
2. 发布 `WorkerFailoverEvent` 事件
3. `FailoverCoordinator.failoverWorker()` 处理故障转移
4. 获取需要故障转移的任务
5. `TaskFailover.failoverTask()` 处理每个任务
6. 更新任务状态
7. 重新分发任务

### 7.3 全局故障转移

**触发时机**: Master 节点启动时

**处理流程**:
1. 发布 `GlobalMasterFailoverEvent` 事件
2. `FailoverCoordinator.globalMasterFailover()` 处理
3. 查询所有需要故障转移的 Master 节点
4. 对每个 Master 节点执行故障转移

## 10. 配置详解

### 10.1 MasterConfig 配置项

```yaml
master:
  listen-port: 5678  # RPC 监听端口
  workflow-event-bus-fire-thread-count: 17  # 工作流事件总线线程数
  master-sync-task-executor-thread-pool-size: 8  # 同步任务执行线程池大小
  master-async-task-executor-thread-pool-size: 8  # 异步任务执行线程池大小
  max-heartbeat-interval: 10s  # 最大心跳间隔
  server-load-protection:  # 服务器负载保护
    max-cpu-usage: 0.8  # 最大 CPU 使用率
    max-memory-usage: 0.8  # 最大内存使用率
    max-jvm-memory-usage: 0.8  # 最大 JVM 内存使用率
  registry-disconnect-strategy:  # 注册中心断开连接策略
    strategy: waiting  # waiting/stop
    max-waiting-time: 60s  # 最大等待时间
  worker-group-refresh-interval: 10s  # Worker 组刷新间隔
  command-fetch-strategy:  # 命令获取策略
    fetch-size: 10  # 每次获取命令数量
    fetch-interval: 1s  # 获取间隔
  worker-load-balancer:  # Worker 负载均衡配置
    type: round-robin  # round-robin/random/fixed-weight/dynamic-weight
```

### 10.2 负载保护配置

## 14. 常见问题排查

### 14.1 命令不消费

**可能原因**:
- 服务器过载
- 命令获取策略配置问题
- 数据库连接问题

**排查方法**:
- 检查服务器负载指标
- 检查命令获取日志
- 检查数据库连接状态

### 14.2 任务分发失败

**可能原因**:
- Worker 节点不可用
- RPC 调用超时
- 网络问题

**排查方法**:
- 检查 Worker 集群状态
- 检查 RPC 调用日志
- 检查网络连接

### 14.3 故障转移不生效

**可能原因**:
- 故障转移事件未触发
- 故障转移锁竞争
- 工作流状态异常

**排查方法**:
