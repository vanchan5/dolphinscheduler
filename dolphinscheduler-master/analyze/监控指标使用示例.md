# Master Server 未捕获异常监控指标使用指南

## 一、指标说明

**指标名称**: `ds.master.uncached.exception`  
**指标类型**: Gauge（仪表盘类型，实时值）  
**指标描述**: Master Server 中未捕获异常的数量

## 二、如何查看指标

### 1. 通过 Prometheus 端点查看

#### 步骤 1: 启用 Metrics
在 `application.yaml` 中确保启用了 metrics：

```yaml
metrics:
  enabled: true

management:
  endpoints:
    web:
      exposure:
        include: health,metrics,prometheus
```

#### 步骤 2: 访问 Prometheus 端点
启动 Master Server 后，访问：

```bash
# 查看所有指标
curl http://localhost:5679/actuator/prometheus

# 或者只查看未捕获异常指标（在 Prometheus 中，点会被转换为下划线）
curl http://localhost:5679/actuator/prometheus | grep ds_master_uncached_exception
```

**输出示例**：
```
# HELP ds_master_uncached_exception number of uncached exception
# TYPE ds_master_uncached_exception gauge
ds_master_uncached_exception 0.0
```

### 2. 在 Prometheus 中查询

如果配置了 Prometheus 采集，可以在 Prometheus UI 中查询：

```promql
# 查询当前未捕获异常数量
ds_master_uncached_exception

# 查询异常增长速率（每分钟）
rate(ds_master_uncached_exception[1m])

# 查询异常总数增长
increase(ds_master_uncached_exception[5m])
```

### 3. 在 Grafana 中可视化

可以在 Grafana 中创建面板监控这个指标：

```promql
# 面板查询
ds_master_uncached_exception
```

## 三、如何验证监控是否生效

### 方法 1: 通过测试代码验证

参考 `ThreadUtilsTest.java` 中的测试：

```java
@Test
void testUncaughtException() throws InterruptedException {
    // 创建一个线程池，执行会抛出异常的任务
    ThreadPoolExecutor threadPoolExecutor = 
        ThreadUtils.newDaemonFixedThreadExecutor("TestThread", 1);
    
    // 执行一个会抛出异常的任务
    threadPoolExecutor.execute(() -> {
        throw new IllegalArgumentException("Test exception");
    });
    
    // 等待异常处理
    Thread.sleep(1_000);
    
    // 验证异常计数增加
    assertEquals(1, DefaultUncaughtExceptionHandler.getUncaughtExceptionCount());
    
    // 此时访问 Prometheus 端点，应该能看到 ds_master_uncached_exception = 1.0
}
```

### 方法 2: 手动触发异常

创建一个测试类来触发未捕获异常：

```java
public class TestUncaughtException {
    public static void main(String[] args) throws InterruptedException {
        // 创建一个新线程并抛出异常
        Thread thread = new Thread(() -> {
            throw new RuntimeException("Test uncaught exception");
        });
        thread.start();
        thread.join();
        
        // 等待异常处理
        Thread.sleep(1000);
        
        // 查看异常计数
        System.out.println("Uncaught exception count: " + 
            DefaultUncaughtExceptionHandler.getUncaughtExceptionCount());
    }
}
```

### 方法 3: 通过 HTTP 请求验证

1. **启动 Master Server**
2. **触发一个未捕获异常**（可以通过代码或测试）
3. **查询指标**：
   ```bash
   curl http://localhost:5679/actuator/prometheus | grep ds_master_uncached_exception
   ```
4. **观察指标值变化**：应该从 0 增加到实际异常数量

## 四、实际应用场景

### 1. 监控告警

在 Prometheus AlertManager 中配置告警规则：

```yaml
groups:
  - name: dolphinscheduler
    rules:
      - alert: MasterUncaughtExceptionHigh
        expr: ds_master_uncached_exception > 10
        for: 5m
        labels:
          severity: warning
        annotations:
          summary: "Master Server 未捕获异常数量过高"
          description: "Master Server 在 5 分钟内未捕获异常数量达到 {{ $value }}"
```

### 2. 日志关联

当指标值增加时，可以查看日志：

```bash
# 查看异常日志（DefaultUncaughtExceptionHandler 会记录日志）
grep "Caught an exception" master-server.log
```

### 3. 性能分析

通过监控异常趋势，可以：
- 识别系统稳定性问题
- 发现代码中的潜在 bug
- 评估系统健康状态

## 五、指标工作原理

1. **异常捕获**: `Thread.setDefaultUncaughtExceptionHandler()` 设置全局异常处理器
2. **异常计数**: `DefaultUncaughtExceptionHandler` 使用 `LongAdder` 线程安全地计数
3. **指标注册**: `MasterServerMetrics.registerUncachedException()` 注册 Gauge 指标
4. **实时查询**: 每次 Prometheus 采集时，通过方法引用 `getUncaughtExceptionCount()` 获取最新值

## 六、注意事项

1. **指标类型**: 这是一个 Gauge 类型，表示当前时刻的值，不是累计值
2. **线程安全**: 使用 `LongAdder` 确保多线程环境下的线程安全
3. **日志记录**: 异常会被记录到日志中，便于排查问题
4. **性能影响**: 异常处理逻辑很轻量，对性能影响极小

## 七、相关指标

其他服务器也有类似的指标：
- `ds.worker.uncached.exception` - Worker Server 未捕获异常
- `ds.api.uncached.exception` - API Server 未捕获异常  
- `ds.alert.uncached.exception` - Alert Server 未捕获异常

可以通过这些指标全面监控整个 DolphinScheduler 集群的异常情况。
