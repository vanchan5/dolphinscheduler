## 1. delete - 删除节点

### 1.1 方法签名

```java
@Override
public void delete(String nodePath)
```

**位置**: `ZookeeperRegistry.java:278-288`

### 1.2 功能说明

删除 ZooKeeper 中的指定节点及其所有子节点。该方法实现了 `Registry` 接口的删除操作，是 ZooKeeper 注册中心的核心方法之一。

### 1.3 参数说明

- **nodePath** (`String`): 要删除的节点路径
    - 必须是有效的 ZooKeeper 路径（如：`/dolphinscheduler/nodes/master/127.0.0.1:5678`）
    - 路径可以是绝对路径，会根据配置的 `namespace` 自动拼接前缀
    - 如果路径不存在，方法会静默处理（不会抛出异常）

### 1.4 返回值

- **void**: 无返回值
- 删除成功时正常返回
- 节点不存在时静默处理，不会抛出异常

### 1.5 实现原理

```java
@Override
public void delete(String nodePath) {
    try {
        client.delete()
                .deletingChildrenIfNeeded()  // 递归删除所有子节点
                .forPath(nodePath);
    } catch (KeeperException.NoNodeException ignored) {
        // Is already deleted or does not exist
        // 节点不存在时，静默处理，不抛出异常
    } catch (Exception e) {
        throw new RegistryException("Failed to delete registry key: " + nodePath, e);
    }
}
```

**核心实现步骤**：

1. **调用 CuratorFramework 删除 API**：
    - 使用 `client.delete()` 创建删除构建器
    - `.deletingChildrenIfNeeded()`：如果节点有子节点，会递归删除所有子节点
    - `.forPath(nodePath)`：指定要删除的节点路径

2. **异常处理**：
    - `KeeperException.NoNodeException`：节点不存在异常，静默忽略（幂等性设计）
    - 其他异常：包装为 `RegistryException` 抛出

### 1.6 关键特性

- **递归删除**：使用 `deletingChildrenIfNeeded()` 确保删除节点及其所有子节点
- **幂等性**：节点不存在时不会抛出异常，可以安全地多次调用
- **异常封装**：将 ZooKeeper 异常统一封装为 `RegistryException`

### 1.7 使用场景

- 服务下线时删除注册节点
- 清理临时数据或过期数据
- 删除整个子树（如删除某个服务的所有子节点）

### 1.8 注意事项

- ⚠️ **谨慎使用**：`deletingChildrenIfNeeded()` 会递归删除所有子节点，确保路径正确
- ⚠️ **权限要求**：需要有删除节点的权限（ACL 权限控制）
- ✅ **线程安全**：CuratorFramework 客户端是线程安全的，可以并发调用

## 2. put - 创建或更新节点

### 2.1 方法签名

```java
@Override
public void put(String key, String value, boolean deleteOnDisconnect)
```

**位置**: `ZookeeperRegistry.java:252-264`

### 2.2 功能说明

创建或更新 ZooKeeper 节点数据。如果节点不存在则创建，如果存在则更新其数据。支持两种节点类型：持久节点（PERSISTENT）和临时节点（EPHEMERAL）。

### 2.3 参数说明

- **key** (`String`): 节点路径
    - 必须是有效的 ZooKeeper 路径
    - 路径会根据配置的 `namespace` 自动拼接前缀

- **value** (`String`): 节点存储的数据
    - 字符串类型，内部转换为 UTF-8 字节数组存储
    - 不能为 null

- **deleteOnDisconnect** (`boolean`): 是否在断开连接时自动删除节点
    - `true`: 创建临时节点（EPHEMERAL），客户端断开连接后节点自动删除
    - `false`: 创建持久节点（PERSISTENT），节点会永久存在直到手动删除

### 2.4 返回值

- **void**: 无返回值
- 创建或更新成功时正常返回

### 2.5 实现原理

```java
@Override
public void put(String key, String value, boolean deleteOnDisconnect) {
    final CreateMode mode = deleteOnDisconnect ? CreateMode.EPHEMERAL : CreateMode.PERSISTENT;

    try {
        client.create()
                .orSetData()                        // 如果节点存在则更新数据，不存在则创建
                .creatingParentsIfNeeded()         // 如果父节点不存在则自动创建
                .withMode(mode)                    // 设置节点类型：EPHEMERAL 或 PERSISTENT
                .forPath(key, value.getBytes(StandardCharsets.UTF_8));
    } catch (Exception e) {
        throw new RegistryException("Failed to put registry key: " + key, e);
    }
}
```

**核心实现步骤**：

1. **确定节点类型**：
    - `deleteOnDisconnect == true` → `CreateMode.EPHEMERAL`（临时节点）
    - `deleteOnDisconnect == false` → `CreateMode.PERSISTENT`（持久节点）

2. **调用 CuratorFramework 创建/更新 API**：
    - `client.create()`: 创建构建器
    - `.orSetData()`: **关键特性**，如果节点已存在则更新数据，不存在则创建（幂等性）
    - `.creatingParentsIfNeeded()`: 如果父节点不存在，自动创建所有父节点
    - `.withMode(mode)`: 设置节点类型
    - `.forPath(key, value.getBytes(StandardCharsets.UTF_8))`: 指定路径和数据（UTF-8 编码）

### 2.6 关键特性

- **幂等性**：使用 `orSetData()` 确保可以安全地多次调用（更新已存在的节点）
- **自动创建父节点**：`creatingParentsIfNeeded()` 自动创建所有不存在的父节点
- **临时节点支持**：通过 `EPHEMERAL` 模式实现服务注册自动清理机制
- **字符编码**：使用 UTF-8 编码存储字符串数据

### 2.7 节点类型说明

#### 2.7.1 PERSISTENT（持久节点）
- 节点创建后永久存在
- 即使客户端断开连接，节点仍然存在
- 适用于存储配置、元数据等需要持久化的数据
- 使用场景：配置中心、元数据存储

#### 2.7.2 EPHEMERAL（临时节点）
- 节点生命周期与客户端会话绑定
- 客户端断开连接后，ZooKeeper 服务器会自动删除该节点
- 适用于服务注册、心跳检测等场景
- 使用场景：服务注册（Master/Worker 注册）

### 2.8 使用场景

- **服务注册**：`put("/nodes/master/127.0.0.1:5678", "metadata", true)` - 注册 Master 服务（临时节点）
- **配置存储**：`put("/config/timeout", "30000", false)` - 存储配置信息（持久节点）
- **节点更新**：更新已存在节点的数据

### 2.9 注意事项

- ⚠️ **临时节点限制**：临时节点不能有子节点，如果需要子节点应使用持久节点
- ⚠️ **会话超时**：临时节点在会话超时（sessionTimeout）后会被删除，确保心跳机制正常工作
- ✅ **数据大小**：ZooKeeper 单个节点数据大小限制为 1MB，注意 value 大小
- ✅ **路径格式**：路径必须以 `/` 开头，不能以 `/` 结尾（根节点除外）

## 3. exists - 检查节点是否存在

### 3.1 方法签名

```java
@Override
public boolean exists(String key)
```

**位置**: `ZookeeperRegistry.java:243-249`

### 3.2 功能说明

检查指定的 ZooKeeper 节点是否存在。这是一个轻量级的查询操作，不会返回节点数据，只返回存在性判断。

### 3.3 参数说明

- **key** (`String`): 要检查的节点路径
    - 必须是有效的 ZooKeeper 路径
    - 路径会根据配置的 `namespace` 自动拼接前缀

### 3.4 返回值

- **boolean**:
    - `true`: 节点存在
    - `false`: 节点不存在

### 3.5 实现原理

```java
@Override
public boolean exists(String key) {
    try {
        return null != client.checkExists().forPath(key);
    } catch (Exception e) {
        throw new RegistryException("zookeeper check key is existed error", e);
    }
}
```

**核心实现步骤**：

1. **调用 CuratorFramework 检查 API**：
    - `client.checkExists()`: 创建存在性检查构建器
    - `.forPath(key)`: 指定要检查的节点路径
    - 返回 `Stat` 对象（节点状态信息）或 `null`（节点不存在）

2. **判断结果**：
    - `Stat != null` → 节点存在 → 返回 `true`
    - `Stat == null` → 节点不存在 → 返回 `false`

3. **异常处理**：
    - 所有异常包装为 `RegistryException` 抛出

### 3.6 关键特性

- **轻量级操作**：只检查节点存在性，不获取节点数据，性能开销小
- **同步操作**：同步调用，立即返回结果
- **异常封装**：统一异常处理，便于上层调用

### 3.7 使用场景

- 判断服务节点是否存在（如检查 Master 是否已注册）
- 前置条件检查（如删除节点前检查是否存在）
- 节点状态监控
- 条件判断逻辑（如配置是否存在）

### 3.8 注意事项

- ✅ **性能**：相比 `get()` 方法，`exists()` 不获取数据，性能更好
- ⚠️ **时序问题**：由于分布式系统的特性，`exists()` 返回 `true` 后，节点可能被其他客户端删除，存在竞态条件
- ✅ **线程安全**：CuratorFramework 客户端是线程安全的，可以并发调用

## 4. isConnected - 检查连接状态

### 4.1 方法签名

```java
@Override
public boolean isConnected()
```

**位置**: `ZookeeperRegistry.java:376-378`

### 4.2 功能说明

检查 CuratorFramework 客户端与 ZooKeeper 服务器之间的连接状态。这是一个状态查询方法，返回当前时刻的连接状态。

### 4.3 参数说明

- 无参数

### 4.4 返回值

- **boolean**:
    - `true`: 客户端已连接到 ZooKeeper 服务器
    - `false`: 客户端未连接到 ZooKeeper 服务器

### 4.5 实现原理

```java
@Override
public boolean isConnected() {
    return client.getZookeeperClient().isConnected();
}
```

**核心实现步骤**：

1. **获取底层 ZooKeeper 客户端**：
    - `client.getZookeeperClient()`: 获取 CuratorFramework 底层封装的 ZooKeeper 客户端

2. **检查连接状态**：
    - `isConnected()`: 检查底层客户端的连接状态
    - 返回当前时刻的连接状态（实时状态，可能存在时序问题）

### 4.6 关键特性

- **实时状态**：返回当前时刻的连接状态，不保证后续状态
- **轻量级**：只查询状态，不涉及网络操作
- **无阻塞**：本地状态查询，不会阻塞线程
- **底层查询**：直接查询底层 ZooKeeper 客户端的连接状态

### 4.7 使用场景

- 健康检查：定期检查连接状态，确保客户端正常工作
- 前置条件判断：在执行关键操作前检查连接状态
- 监控告警：连接断开时触发告警机制
- 条件判断：根据连接状态决定是否执行某些操作

### 4.8 注意事项

- ⚠️ **时序问题**：`isConnected()` 返回的是**当前时刻**的状态，调用后连接状态可能立即改变
- ⚠️ **不能替代监听器**：不能使用轮询 `isConnected()` 的方式替代连接状态监听器，应该使用 `addConnectionStateListener()` 监听连接状态变化
- ✅ **线程安全**：方法本身是线程安全的，可以并发调用
- ⚠️ **连接状态说明**：`true` 表示当前连接正常，`false` 表示未连接或连接断开

## 5. get - 获取节点数据

### 5.1 方法签名

```java
@Override
public String get(String key) throws RegistryException
```

**位置**: `ZookeeperRegistry.java:234-240`

### 5.2 功能说明

获取 ZooKeeper 中指定节点的数据内容。该方法从 ZooKeeper 服务器读取节点的数据，并将其转换为字符串返回。如果节点不存在，会抛出异常。

### 5.3 参数说明

- **key** (`String`): 要获取数据的节点路径
    - 必须是有效的 ZooKeeper 路径
    - 路径会根据配置的 `namespace` 自动拼接前缀
    - 节点必须存在，否则会抛出异常

### 5.4 返回值

- **String**: 节点存储的数据内容
    - 节点数据以 UTF-8 编码的字符串形式返回
    - 如果节点数据为空，返回空字符串 `""`
    - 节点不存在时会抛出 `RegistryException`

### 5.5 实现原理

```java
@Override
public String get(String key) {
    try {
        return new String(client.getData().forPath(key), StandardCharsets.UTF_8);
    } catch (Exception e) {
        throw new RegistryException("zookeeper get data error", e);
    }
}
```

**核心实现步骤**：

1. **调用 CuratorFramework 获取数据 API**：
    - `client.getData()`: 创建数据获取构建器
    - `.forPath(key)`: 指定要获取数据的节点路径
    - 返回节点数据的字节数组（`byte[]`）

2. **数据转换**：
    - `new String(..., StandardCharsets.UTF_8)`: 将字节数组转换为 UTF-8 编码的字符串
    - 确保数据编码的一致性

3. **异常处理**：
    - 所有异常（包括节点不存在异常）统一包装为 `RegistryException` 抛出

### 5.6 关键特性

- **同步操作**：同步调用，等待服务器响应后返回数据
- **UTF-8 编码**：数据统一使用 UTF-8 编码进行字符串转换
- **完整数据**：获取节点的完整数据内容（相比 `exists()` 会返回实际数据）
- **异常处理**：节点不存在时抛出异常，调用方需要处理异常

### 5.7 使用场景

- 读取配置信息（如系统配置、服务配置）
- 获取服务元数据（如 Master/Worker 的注册信息）
- 读取节点状态数据
- 获取存储的业务数据

### 5.8 注意事项

- ⚠️ **节点必须存在**：节点不存在时会抛出异常，使用前建议先用 `exists()` 检查
- ⚠️ **数据大小限制**：ZooKeeper 单个节点数据大小限制为 1MB，超过限制会抛出异常
- ⚠️ **性能考虑**：相比 `exists()` 方法，`get()` 需要传输数据，性能开销更大
- ✅ **线程安全**：CuratorFramework 客户端是线程安全的，可以并发调用
- ⚠️ **时序问题**：获取数据后，节点数据可能被其他客户端修改，存在竞态条件

## 6. children - 获取子节点列表

### 6.1 方法签名

```java
@Override
public List<String> children(String key)
```

**位置**: `ZookeeperRegistry.java:267-275`

### 6.2 功能说明

获取 ZooKeeper 中指定节点的所有直接子节点名称列表。该方法只返回子节点的名称，不返回子节点的数据。返回的列表会按照**倒序**排列（reverse order）。

### 6.3 参数说明

- **key** (`String`): 父节点路径
    - 必须是有效的 ZooKeeper 路径
    - 路径会根据配置的 `namespace` 自动拼接前缀
    - 必须是目录节点（可以有子节点），如果是叶子节点会抛出异常

### 6.4 返回值

- **List<String>**: 子节点名称列表
    - 如果没有子节点，返回空列表（不是 `null`）
    - 列表中的元素是子节点的名称（不包含父路径）
    - 列表按照**倒序**（reverse order）排列

### 6.5 实现原理

```java
@Override
public List<String> children(String key) {
    try {
        List<String> result = client.getChildren().forPath(key);
        result.sort(Comparator.reverseOrder());
        return result;
    } catch (Exception e) {
        throw new RegistryException("zookeeper get children error", e);
    }
}
```

**核心实现步骤**：

1. **调用 CuratorFramework 获取子节点 API**：
    - `client.getChildren()`: 创建子节点列表获取构建器
    - `.forPath(key)`: 指定父节点路径
    - 返回子节点名称列表（`List<String>`）

2. **列表排序**：
    - `result.sort(Comparator.reverseOrder())`: 对列表进行倒序排序
    - 使用 `Comparator.reverseOrder()` 实现字典序倒序排列
    - **注意**：排序是就地操作（in-place），会修改原列表

3. **异常处理**：
    - 所有异常统一包装为 `RegistryException` 抛出

### 6.6 关键特性

- **只返回名称**：只返回子节点的名称，不包含完整路径，也不返回子节点的数据
- **倒序排列**：列表按照字典序倒序排列（reverse order）
- **轻量级操作**：相比获取每个子节点的数据，`children()` 只获取名称列表，性能开销较小
- **空列表处理**：没有子节点时返回空列表，而不是 `null`

### 6.7 排序说明

**倒序排列示例**：

假设节点 `/parent` 有以下子节点：
- `node-a`
- `node-b`
- `node-c`
- `node-1`
- `node-2`

使用 `Comparator.reverseOrder()` 排序后，返回顺序为：
1. `node-c`
2. `node-b`
3. `node-a`
4. `node-2`
5. `node-1`

**排序原因**：可能是为了在列表展示时，将较新的节点（按字典序）排在前面，或者在处理时按照特定顺序处理。

### 6.8 使用场景

- 获取服务节点列表（如获取所有 Master 节点：`children("/nodes/master")`）
- 遍历目录结构
- 服务发现（获取某个路径下的所有服务实例）
- 统计子节点数量

### 6.9 注意事项

- ⚠️ **只返回直接子节点**：只返回一级子节点，不包括子节点的子节点（递归获取需要自己实现）
- ⚠️ **节点必须是目录**：如果节点是叶子节点（没有子节点能力），会抛出异常
- ✅ **空列表处理**：没有子节点时返回空列表，调用方可以安全地使用 `isEmpty()` 判断
- ⚠️ **时序问题**：获取列表后，子节点可能被其他客户端添加或删除，存在竞态条件
- ✅ **线程安全**：CuratorFramework 客户端是线程安全的，可以并发调用
- ⚠️ **排序影响**：返回的列表是排序后的结果，如果需要原始顺序，需要自己实现

## 总结

本文档详细分析了 `ZookeeperRegistry` 类中的 6 个核心客户端方法：

1. **delete** - 递归删除节点及其所有子节点，具有幂等性
2. **put** - 创建或更新节点，支持持久节点和临时节点
3. **exists** - 轻量级检查节点存在性，不获取数据
4. **isConnected** - 查询当前连接状态，实时状态但不保证后续
5. **get** - 获取节点数据，返回 UTF-8 编码的字符串
6. **children** - 获取子节点列表，按倒序排列

这些方法都是基于 CuratorFramework 实现的，提供了统一的异常处理和线程安全保障，是 DolphinScheduler 注册中心功能的基础。
