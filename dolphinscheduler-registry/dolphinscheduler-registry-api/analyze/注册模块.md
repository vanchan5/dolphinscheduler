# dolphinscheduler-registry-api 模块设计与逻辑分析

## 一、整体架构设计

这是一个注册中心 API 模块，采用了 **SPI (Service Provider Interface)** 设计模式，为 DolphinScheduler 提供了抽象的注册中心能力。通过该模块，系统可以支持多种注册中心实现（如 Zookeeper、Etcd、MySQL/JDBC），实现了注册中心的插件化。

### 核心设计理念

- **SPI 模式**：`Registry` 接口作为 SPI 接口，支持插件化实现
- **分层设计**：API 层定义接口，Client 层提供业务封装，Plugin 层提供具体实现
- **事件驱动**：通过订阅机制实现服务上下线感知
- **高可用支持**：内置 HA 选举机制，支持主备切换

## 二、核心组件分析

### 2.1 SPI 接口层：Registry

`Registry` 接口是注册中心的 SPI 接口，定义了注册中心的核心能力：

#### 核心方法

- **连接管理**
  - `start()`: 启动注册中心，建立连接
  - `isConnected()`: 判断是否已连接
  - `connectUntilTimeout(Duration timeout)`: 连接注册中心，支持超时设置

- **数据操作**
  - `get(String key)`: 获取指定 key 的值
  - `put(String key, String value, boolean deleteOnDisconnect)`: 写入键值对
    - `deleteOnDisconnect`: 关键参数，为 true 时创建临时节点，连接断开时自动删除
  - `delete(String key)`: 删除指定 key
  - `exists(String key)`: 检查 key 是否存在
  - `children(String key)`: 获取子节点列表

- **订阅机制**
  - `subscribe(String path, SubscribeListener listener)`: 订阅路径变化，支持事件通知

- **分布式锁**
  - `acquireLock(String key)`: 获取分布式锁
  - `acquireLock(String key, long timeout)`: 获取分布式锁，支持超时
  - `releaseLock(String key)`: 释放分布式锁

- **连接状态监听**
  - `addConnectionStateListener(ConnectionListener listener)`: 添加连接状态监听器

#### 设计亮点

`deleteOnDisconnect` 参数实现了**临时节点**机制，这是服务注册发现的关键：
- 服务注册时使用 `deleteOnDisconnect=true`
- 服务正常运行时，节点存在于注册中心
- 服务异常退出或网络断开时，注册中心自动删除节点
- 其他服务通过订阅机制感知到节点删除，触发服务下线处理

### 2.2 客户端封装层：RegistryClient

`RegistryClient` 是对 `Registry` 的高级封装，提供了业务层面的 API。

#### 主要功能

**1. 节点类型管理**
- 构造函数中初始化 MASTER、WORKER、ALERT_SERVER 等路径
- 确保注册中心的目录结构存在

**2. 服务发现**
- `getServerList(RegistryNodeType registryNodeType)`: 获取指定类型的服务列表
- `getRandomServer(RegistryNodeType registryNodeType)`: 随机获取一个服务（负载均衡）
- `getServerMaps(RegistryNodeType nodeType)`: 获取服务映射（host:port -> value）
- `checkNodeExists(String host, RegistryNodeType nodeType)`: 检查节点是否存在

**3. 心跳解析**
- 将注册中心存储的心跳 JSON 解析为 `Server` 对象
- 支持三种心跳类型：
  - `MasterHeartBeat`: Master 节点心跳
  - `WorkerHeartBeat`: Worker 节点心跳
  - `AlertServerHeartBeat`: Alert 服务器心跳

**4. 持久化操作**
- `persist(String key, String value)`: 持久化存储（`deleteOnDisconnect=false`）
- `persistEphemeral(String key, String value)`: 临时节点（`deleteOnDisconnect=true`）

**5. 故障转移节点清理**
- `cleanHistoryFailoverFinishedNodes()`: 清理 7 天前的故障转移完成节点
- 防止注册中心存储过多的历史数据

#### 代码示例

```java
// 服务注册（临时节点）
// Master/Worker 注册时会调用 persistEphemeral
String masterRegistryPath = masterConfig.getMasterRegistryPath(); // "/nodes/master/ip:port"
MasterHeartBeat heartBeat = masterHeartBeatTask.getHeartBeat();
registryClient.persistEphemeral(masterRegistryPath, JSONUtils.toJsonString(heartBeat));

// 服务发现
List<Server> masterList = registryClient.getServerList(RegistryNodeType.MASTER);
// 返回的 Server 对象包含：id, host, port, createTime, lastHeartbeatTime, heartBeatInfo 等信息

// 随机选择一个服务（负载均衡）
Optional<Server> server = registryClient.getRandomServer(RegistryNodeType.WORKER);

// 检查节点是否存在
boolean exists = registryClient.checkNodeExists("192.168.1.100", RegistryNodeType.MASTER);
```

订阅监听器接口：

```java

    void notify(final Event event);
```

#### SubscribeScope 枚举

定义订阅范围：

- `PATH_ONLY`: 仅监听路径本身的变化
- `CHILDREN_ONLY`: 仅监听子节点的变化
- `ALL`: 监听路径、所有子节点以及父路径的变化

#### 使用场景

- **服务上下线感知**：订阅服务节点路径，当节点添加/删除时触发事件
- **配置变更通知**：订阅配置路径，当配置更新时触发事件
- **Leader 选举**：订阅选举路径，当 Leader 节点删除时触发重新选举

### 2.5 高可用（HA）模块

位于 `ha` 包下，提供了高可用选举机制。

#### HAServer 接口

定义了 HA 服务器的核心能力：

```java
public interface HAServer extends AutoCloseable {
    void start();                          // 启动服务器
    boolean isActive();                    // 判断是否激活
    boolean participateElection();         // 参与选举
    void addServerStatusChangeListener(ServerStatusChangeListener listener);
    ServerStatus getServerStatus();        // 获取服务器状态
    void close();
}

enum ServerStatus {
    ACTIVE,   // 激活状态（Leader）
    STAND_BY  //  standby状态（Follower）
}
```

#### AbstractHAServer 抽象实现

提供了 HA 选举的完整实现：

**1. 选举逻辑**

```java
public boolean participateElection() {
    final String electionLock = selectorPath + "-lock";
    // 最多重试 20 次，每次间隔 5 秒
    for (int i = 0; i < DEFAULT_MAX_RETRY_TIMES; i++) {
        try {
            if (registry.acquireLock(electionLock)) {
                if (!registry.exists(selectorPath)) {
                    // 路径不存在，写入自己的标识，成为 Leader
                    registry.put(selectorPath, serverIdentify, true);
                    return true;
                }
                // 路径存在，检查是否是自己
                return serverIdentify.equals(registry.get(selectorPath));
            }
            return false;
        } finally {
            registry.releaseLock(electionLock);
        }
    }
}
```

**选举流程**：
1. 获取分布式锁（`selectorPath + "-lock"`）
2. 检查选举路径是否存在
3. 如果不存在，写入自己的标识，成为 Leader
4. 如果存在，检查是否是自己
5. 释放锁

**重试机制**：
- 最多重试 20 次
- 每次重试间隔 5 秒
- 避免因网络抖动导致选举失败

**2. 订阅机制**

```java
public void start() {
    registry.subscribe(selectorPath, new SubscribeListener() {
        @Override
        public void notify(Event event) {
            if (Event.Type.REMOVE.equals(event.getType())) {
                if (serverIdentify.equals(event.getEventData())) {
                    // 自己的节点被删除，转为 StandBy
                    statusChange(ServerStatus.STAND_BY);
                } else {
                    // 其他节点被删除，尝试参与选举
                    if (participateElection()) {
                        statusChange(ServerStatus.ACTIVE);
                    }
                }
            }
        }
    });
    
    // 启动时参与选举
    if (participateElection()) {
        statusChange(ServerStatus.ACTIVE);
    }
}
```

**状态转换流程**：
1. 启动时订阅选举路径
2. 参与选举，如果成功则转为 ACTIVE
3. 当 Leader 节点被删除时（连接断开），触发重新选举
4. 如果选举成功，转为 ACTIVE；否则保持 STAND_BY

**3. 状态变更通知**

```java
private void statusChange(ServerStatus targetStatus) {
    final ServerStatus originStatus = serverStatus;
    serverStatus = targetStatus;
    synchronized (this) {
        serverStatusChangeListeners.forEach(listener -> 
            listener.change(originStatus, serverStatus)
        );
    }
}
```

#### ServerStatusChangeListener 接口

监听服务器状态变化：

```java
public interface ServerStatusChangeListener {
    void change(final HAServer.ServerStatus originStatus, 
                final HAServer.ServerStatus currentStatus);
}
```

#### AbstractServerStatusChangeListener 抽象类

提供了状态变化处理的模板方法：

```java
public abstract class AbstractServerStatusChangeListener 
    implements ServerStatusChangeListener {
    
    @Override
    public void change(ServerStatus originStatus, ServerStatus currentStatus) {
        if (originStatus == ServerStatus.ACTIVE) {
            if (currentStatus == ServerStatus.STAND_BY) {
                changeToStandBy();  // 从 Active 转为 StandBy
            }
        } else if (originStatus == ServerStatus.STAND_BY) {
            if (currentStatus == ServerStatus.ACTIVE) {
                changeToActive();   // 从 StandBy 转为 Active
            }
        }
    }
    
    public abstract void changeToActive();
    public abstract void changeToStandBy();
}
```

#### DefaultServerStatusChangeListener

默认实现（仅记录日志）：

```java
public class DefaultServerStatusChangeListener 
    extends AbstractServerStatusChangeListener {
    
    @Override
    public void changeToActive() {
        log.info("The status is active now.");
    }
    
    @Override
    public void changeToStandBy() {
        log.info("The status is standby now.");
    }
}
```

### 2.6 节点类型：RegistryNodeType

```java
public enum RegistryNodeType {
```

## 三、设计模式应用

### 3.1 SPI 模式

`Registry` 接口作为 SPI 接口，支持插件化实现：
- 定义标准接口
- 各插件实现接口（Zookeeper、Etcd、JDBC）
- 通过 Spring Boot 自动配置加载实现类

### 3.2 适配器模式

`RegistryClient` 作为适配器，将底层 `Registry` 的 API 适配为业务友好的 API：
- 封装底层复杂性
- 提供业务语义明确的方法
- 处理数据转换（JSON -> Server 对象）

### 3.3 观察者模式

多个监听器接口实现了观察者模式：
- `ConnectionListener`: 监听连接状态变化
- `SubscribeListener`: 监听注册中心事件
- `ServerStatusChangeListener`: 监听服务器状态变化

### 3.4 模板方法模式

- `AbstractHAServer`: 提供选举框架，子类可扩展
- `AbstractServerStatusChangeListener`: 提供状态变化处理框架，子类实现具体逻辑

### 3.5 策略模式

- `ConnectStrategy`: 定义连接策略，不同场景可以有不同的重连策略

## 四、核心流程分析

### 4.1 注册中心启动流程

```
Registry.start()
    ↓
连接到注册中心
    ↓
初始化节点路径（MASTER、WORKER、ALERT_SERVER）
    ↓
订阅监听路径
    ↓
启动完成
```

### 4.2 服务注册流程

```
RegistryClient.persistEphemeral(key, heartbeatJson)
    ↓
Registry.put(key, value, deleteOnDisconnect=true)
    ↓
注册中心存储（临时节点）
    ↓
服务正常运行时，节点持续存在
    ↓
服务异常退出/网络断开
    ↓
注册中心自动删除临时节点
    ↓
其他服务通过订阅机制感知节点删除
    ↓
触发服务下线处理
```

**关键点**：
- 使用临时节点（`deleteOnDisconnect=true`）实现服务自动下线
- 无需显式注销，连接断开即自动清理
- 通过订阅机制实现服务上下线的实时感知

### 4.3 HA 选举流程

```
AbstractHAServer.start()
    ↓
订阅 selectorPath（选举路径）
    ↓
participateElection()
    ↓
获取分布式锁（selectorPath + "-lock"）
    ↓
检查选举路径是否存在
    ├─ 不存在 → 写入自己的标识 → 成为 Leader (ACTIVE)
    └─ 存在 → 检查是否是自己 → 是则 ACTIVE，否则 STAND_BY
    ↓
释放分布式锁
    ↓
状态变更，通知监听器
    ↓
Leader 节点异常断开连接
    ↓
订阅监听到节点删除事件
    ↓
其他节点重新参与选举
    ↓
选举成功 → 转为 ACTIVE
```

**选举机制特点**：
- 使用分布式锁保证选举的原子性
- 支持重试机制（最多20次，间隔5秒）避免网络抖动
- 通过订阅机制实现故障检测和自动切换

### 4.4 服务发现流程

```
RegistryClient.getServerList(RegistryNodeType.MASTER)
    ↓
getServerMaps(nodeType)
    ↓
registry.children(nodeType.getRegistryPath())
    ↓
遍历子节点，获取每个节点的值
    ↓
解析心跳 JSON
    ├─ MasterHeartBeat → Server 对象
    ├─ WorkerHeartBeat → Server 对象
    └─ AlertServerHeartBeat → Server 对象
    ↓
返回 Server 列表
```

**Server 对象包含**：
- `id`: 进程 ID
- `host`: 主机地址
- `port`: 端口号
- `createTime`: 创建时间（启动时间）
- `lastHeartbeatTime`: 最后心跳时间
- `heartBeatInfo`: 原始心跳 JSON
- `serverDirectory`: 服务器在注册中心的路径

### 4.5 订阅监听流程

```
Registry.subscribe(path, SubscribeListener)
    ↓
注册中心开始监听路径变化
    ↓
路径发生变化（ADD/REMOVE/UPDATE）
    ↓
注册中心生成 Event 对象
    ├─ watchedPath: 被监听的路径
    ├─ eventPath: 事件发生的完整路径
    ├─ eventData: 事件对应的值
    └─ type: 事件类型（ADD/REMOVE/UPDATE）
    ↓
根据 SubscribeScope 过滤事件
    ├─ PATH_ONLY: 仅路径本身
    ├─ CHILDREN_ONLY: 仅子节点
    └─ ALL: 路径+子节点+父路径
    ↓
调用 SubscribeListener.notify(Event)
    ↓
业务逻辑处理
```

## 五、设计亮点总结

### 5.1 临时节点机制

**核心设计**：`deleteOnDisconnect` 参数

- **服务注册**：使用临时节点，连接断开自动删除
- **自动清理**：无需显式注销，避免僵尸节点
- **故障检测**：服务异常退出时自动触发下线事件

### 5.2 分布式锁机制

**应用场景**：
- HA 选举：保证选举过程的原子性
- 故障转移：防止多个节点同时执行故障转移
- 任务协调：任务组协调、串行工作流协调等

**实现方式**：
- 通过 `acquireLock()` 和 `releaseLock()` 方法
- 支持超时机制，避免死锁
- 各注册中心实现提供底层支持

### 5.3 事件驱动架构

**优势**：
- **实时性**：服务上下线即时感知
- **解耦**：通过事件通知实现组件解耦
- **可扩展**：易于添加新的事件监听器

**事件类型**：
- `ADD`: 节点添加（服务上线）
- `REMOVE`: 节点删除（服务下线）
- `UPDATE`: 节点更新（配置变更、心跳更新）

### 5.4 重试机制

**HA 选举重试**：
- 最多重试 20 次
- 每次间隔 5 秒
- 避免因网络抖动导致选举失败

**意义**：
- 提高系统容错能力
- 减少因临时故障导致的选举失败
- 保证系统的高可用性

### 5.5 路径标准化

**RegistryNodeType 枚举**：
- 统一路径命名规范
- 避免路径硬编码
- 便于路径管理和维护

**路径分类**：
- `/nodes/*`: 服务节点目录
- `/lock/*`: 分布式锁目录
- 每种节点类型都有对应的路径定义

### 5.6 故障转移记录

**FAILOVER_FINISH_NODES**：
- 记录已完成故障转移的节点
- 路径格式：`/nodes/failover-finish-nodes/{serverAddress}-{startupTime}-{processId}`
- 自动清理 7 天前的记录
- 避免重复处理同一个故障节点

- 主要用于远程调用相关功能

## 八、使用建议

### 8.1 服务注册

**推荐做法**：
- 使用 `persistEphemeral()` 注册服务（临时节点）
- 定期发送心跳更新节点值
- 不需要显式注销，连接断开自动清理

### 8.2 服务发现

**推荐做法**：
- 使用 `getServerList()` 获取服务列表
- 使用 `getRandomServer()` 实现负载均衡
- 结合订阅机制实现服务列表的实时更新

### 8.3 HA 选举

**推荐做法**：
- 使用 `AbstractHAServer` 作为基类
- 实现 `AbstractServerStatusChangeListener` 处理状态变更
- 在状态变为 ACTIVE 时启动业务逻辑
- 在状态变为 STAND_BY 时停止业务逻辑

### 8.4 分布式锁

**推荐做法**：
- 使用 `getLock()` 获取锁，`releaseLock()` 释放锁
- 确保在 finally 块中释放锁
- 使用超时机制避免长时间等待

## 九、注意事项

### 9.1 临时节点

- 使用 `persistEphemeral()` 创建的节点会在连接断开时自动删除
- 需要保持连接活跃，否则节点会被删除
- 适合服务注册，不适合持久化配置

### 9.2 分布式锁

- 必须在 finally 块中释放锁
- 避免死锁，使用超时机制
- 锁的持有时间应尽可能短

### 9.3 订阅监听

- 订阅是异步的，事件可能会延迟
- 需要处理事件处理的异常，避免影响其他监听器
- 注意订阅范围（SubscribeScope）的选择

### 9.4 路径管理

- 使用 `RegistryNodeType` 枚举，避免硬编码路径
- 路径应符合命名规范
- 注意路径的层次结构

## 十、总结

`dolphinscheduler-registry-api` 模块是 DolphinScheduler 分布式架构的基础组件，它提供了：

1. **抽象的注册中心能力**：通过 SPI 模式支持多种注册中心实现
2. **服务注册发现**：基于临时节点和订阅机制实现服务管理
3. **高可用支持**：内置 HA 选举机制，支持主备切换
4. **分布式协调**：提供分布式锁和事件通知能力
5. **良好的扩展性**：支持插件化和自定义扩展

该模块的设计充分考虑了分布式系统的特点，提供了完善的功能和良好的扩展性，为 DolphinScheduler 的分布式部署提供了坚实的基础。
